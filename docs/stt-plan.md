# 음성 질의 확장 기획서 (v2)

기간: 3일 (10/13 ~ 10/15) · v1 대비 변경점은 [부록 A](#부록-a-v1에서-바뀐-것)

---

## 1. 목적

한 줄 목표: **음성 질문이 들어와도 근거 없는 답변 0건을 유지하고,
어느 구간이 느려지거나 멈춰도 정해진 시간 안에 안전한 응답을 돌려준다.**

| 채울 공백 | 이 확장으로 생기는 근거 |
|---|---|
| STT (음성 → 텍스트) | 음성 질문을 받아 기존 파이프라인에 연결 |
| 지연·장애 대응 | 구간별 지연 측정, 데드라인, 대체 경로, 장애 주입 |
| 백엔드 API | FastAPI 음성 질의 엔드포인트 |

TTS는 만들지 않습니다 (다른 프로젝트에서 출시 경험 확보).

---

## 2. 범위

**포함** — 음성(wav) → STT → 기존 파이프라인 → 텍스트 응답, 구간별 지연 측정,
데드라인과 대체 경로, 워밍업, 장애 주입 테스트, FastAPI 엔드포인트 1개.

**제외**

| 항목 | 이유 |
|---|---|
| TTS | 범위 밖 |
| 실시간 스트리밍(WebSocket) | 3일 초과. 면접에서 "다음 단계"로 설명 |
| 전화망 연동 | 범위 초과 |
| 동시 접속·부하 테스트 | 단일 사용자 로컬 환경으로 명시 |
| **가드 임계값 재조정** | 0.56 / 0.50을 음성에 맞춰 바꾸지 않는다. 바꾸면 기존 평가가 무효가 된다 |
| **조항 번호 정규식 확장** | 아래 3-2 참고. 오탐을 새로 만든다 |

## 3. 설계 결정

### 3-1. STT는 로컬에서 실행한다

외부 STT API를 쓰면 "사내 문서와 질문이 외부로 나가지 않는다"는 핵심 제약이 깨집니다.
`faster-whisper`를 로컬 GPU에서 돌립니다.

### 3-2. 조항 번호 정규식은 넓히지 않는다

STT가 `"제27조"`를 `"27조"`로 받아쓸 수 있습니다. 현재 정규식은 `제\s*(\d+)\s*조` 라
`제`가 없으면 매칭되지 않습니다. 그렇다고 `제?\s*(\d+)\s*조` 로 넓히면 **오탐이 생깁니다.**

```
3조 2교대 근무는 어떻게 돼?   → 제3조(용어의 정의) 조회
2조 격일제로 일하면 수당은?    → 제2조(적용범위) 조회
1조당 인원이 몇 명이야?        → 제1조(목적) 조회
```

규정에 없는 질문이 거부되지 않고 **엉뚱한 조항을 정확 일치(1.0)로 반환**합니다.
가드를 우회하는 경로라 단순 오인식보다 나쁩니다. 그래서 정규식은 그대로 둡니다.

대신 `제` 누락 변형 2~3개를 **점수에 넣지 않고 관찰로만** 기록하고,
README 다음 단계에 "'제' 누락 처리 시 교대조 표현과의 충돌 검토 필요"로 남깁니다.

### 3-3. 한글 숫자 정규화는 STT 출력에만 적용한다

Whisper가 `"제 이십칠 조"` 처럼 한글 숫자로 받아쓰면 정규식이 실패합니다.
한글 숫자 → 아라비아 숫자 변환을 **STT 출력 직후에만** 넣습니다.
텍스트 입력 경로는 손대지 않으므로 기존 평가 결과가 그대로 유지됩니다.

정규화 **전/후 인식률을 둘 다 기록**해 "문제 발견 → 해결"을 숫자로 남깁니다.

### 3-4. 데드라인은 음성 경로 전용 함수에만 건다

`ollama.chat()`은 블로킹이라 중간에 끊을 수 없습니다. 스트리밍(`stream=True`)으로 받으면서
데드라인을 검사하고, 넘기면 **부분 답변을 버리고** 근거 조항 원문을 반환합니다.
중간에 잘린 답은 틀린 답이 될 수 있어, "불확실하면 지어내지 않는다"는 원칙과 맞춥니다.

기존 `answer_with_history()`는 **수정하지 않습니다.** 음성 경로 전용 함수를 새로 만듭니다.

> 스트리밍을 중단해도 Ollama 서버는 생성을 계속할 수 있습니다.
> 제너레이터를 닫아 연결을 끊고, `ollama ps` 로 실제로 멈췄는지 확인합니다.

스트리밍을 쓰면 **TTFT(첫 토큰까지 시간)** 도 측정할 수 있습니다.
음성에서는 이 값이 전체 시간보다 체감에 가깝습니다.

## 4. 구조

```
음성 파일(wav)
  → [STT]            faster-whisper, 로컬 GPU
  → [숫자 정규화]     한글 숫자 → 아라비아 숫자 (STT 출력에만)
  → [임베딩 + 검색]   bge-m3, NumPy 벡터 스토어          (기존)
  → [가드 판정]       judge_evidence()                   (기존, 변경 없음)
  → [LLM 생성]        Ollama qwen2.5:7b, 스트리밍 + 데드라인
  → 텍스트 응답
```

판정은 기존 `judge_evidence()` 를 그대로 공유합니다 — **판정은 공통, 채널만 개별**입니다
(Streamlit / CLI / MCP / HTTP).

## 5. 기능 명세

### F1. STT 입력
- 입력: wav (16kHz 모노)
- 출력: 인식 텍스트, 평균 log 확률, 무음 확률
- 정규화 후 텍스트가 기존 질문 입력과 똑같이 파이프라인에 들어감

### F2. 구간별 지연 측정

기존 JSONL 감사 로그에 필드를 추가합니다. **새 필드 기본값은 `None`** 이라
기존 텍스트 경로 호출이 깨지지 않습니다 (텍스트 입력이면 `stt_ms` 는 `null`).

| 필드 | 의미 |
|---|---|
| `audio_sec` | 입력 음성 길이 |
| `stt_ms` | STT 소요 시간 |
| `normalize_ms` | 숫자 정규화 소요 시간 |
| `retrieval_ms` | 임베딩 + 검색 |
| `guard_ms` | 가드 판정 |
| `ttft_ms` | 첫 토큰까지 시간 |
| `llm_ms` | LLM 생성 (거부 시 0) |
| `total_ms` | 전체 |
| `stt_text_raw` | 정규화 전 STT 원본 |
| `stt_text` | 정규화 후 |
| `fallback` | 대체 경로 종류, 아니면 `null` |

### F3. 지연 예산과 대체 경로

**Day 1 측정 후 재배분합니다.** 아래는 v1 예산을 실측에 맞춰 조정한 초기값입니다.
v1은 검색에 0.3초를 줬지만 실측은 0.01초라 과다 배정이었습니다.

| 구간 | v1 | **v2** | 초과·실패 시 |
|---|---:|---:|---|
| STT | 1.5초 | **1.5초** | 신뢰도 낮으면 "다시 한 번 말씀해 주시겠어요?" |
| 임베딩 + 검색 | 0.3초 | **0.1초** | "확인 후 다시 안내드리겠습니다" |
| 가드 판정 | 0.05초 | *(검색에 포함)* | (기존) 근거 없으면 LLM 호출 없이 즉시 거부 |
| LLM 생성 | 1.0초 | **1.3초** | 부분 답변 버리고 **근거 조항 원문만** 반환 |
| 여유 | 0.15초 | **0.1초** | |
| **합계** | 3.0초 | **3.0초** | |

핵심: LLM이 늦으면 답을 지어내지 않고 근거 원문을 먼저 줍니다.
**"근거 없으면 답하지 않는다"를 시간 축으로 확장**한 것입니다.

### F4. 워밍업
서버 시작 시 bge-m3, STT, qwen2.5를 미리 로드하고 더미 요청 1회.
Ollama `keep_alive` 로 모델이 메모리에서 내려가지 않게 유지.

### F5. 장애 주입 테스트

| 시나리오 | 방법 | 기대 결과 |
|---|---|---|
| LLM 서버 다운 | Ollama 중지 | 근거 조항 원문 반환 |
| LLM 지연 | 생성에 인위적 지연 | 근거 조항 원문 반환 |
| 검색 지연 | 검색 함수에 인위적 지연 | 확인 후 안내 응답 |
| 무음·잡음 입력 | 무음 wav | 재질문 응답 |

### F6. FastAPI 엔드포인트
음성 파일을 받아 응답 텍스트, 근거 조항, 판정, 구간별 지연을 반환합니다.
`fastapi`, `uvicorn` 은 이미 설치돼 있습니다.

## 6. 녹음 세트

**ffmpeg을 쓰지 않습니다.** 질문을 화면에 띄우고 Enter로 16kHz 모노 wav를 저장하는
녹음 스크립트를 만듭니다. 파일명을 질문 ID로 저장하므로 라벨이 섞이지 않고
마이크 조건도 일정하게 유지됩니다.

| 세트 | 개수 | 용도 | 비고 |
|---|---:|---|---|
| **평가셋** | 40 | 보고용 (텍스트 결과와 1:1 비교) | 기존 `QUESTIONS` 30 + `HOLDOUT` 10 |
| **번호 세트** | 15 | 조항 번호 인식률 | 제1~31조 고르게, **`제N조` 형태만** |
| **모델 선택용** | 10 | small/medium 비교 전용 | 평가셋과 겹치지 않음 |
| **관찰용** | 3 | 점수 제외 | `제` 누락 변형, 교대조 표현 |
| **합계** | **68** | | 약 1시간 |

### 6-1. 녹음 규칙 (측정 타당성)

번호 인식률이 **STT 성능이 아니라 읽는 방식의 차이**를 재게 되면 지표가 무의미해집니다.

- 화면에 `제27조`가 떠도 **실제 사용자처럼 자연스럽게 "제이십칠조"** 라고 읽습니다.
  `"제 이 칠 조"` 처럼 숫자를 하나씩 끊어 읽지 않습니다.
- 68개 내내 **같은 방식**으로 읽습니다. 중간에 바뀌면 그 차이가 결과에 섞입니다.
- **마이크와의 거리를 일정하게** 유지합니다.
- 한 번에 몰아서 녹음합니다 (목 상태·주변 소음 변화를 줄이기 위해).

### 6-2. 번호 세트의 숫자 선택

| 조 번호 | 의도 |
|---|---|
| 제2 · 제12 · 제22 | "이 / 십이 / 이십이" 혼동을 직접 확인 |
| 제20 | "이십"은 끝자리가 없어 `제2조`나 금액 `20조`로 흘릴 위험 |
| 제31 | 마지막 조항, 경계값 |

한 자리 5개 / 두 자리 10개로 맞췄습니다.

모델 선택을 평가셋 40문항으로 하면 **같은 데이터로 고르고 보고하는** 구조가 됩니다.
가드 임계값에 홀드아웃을 둔 것과 같은 이유로, 모델 선택용 10문항을 따로 둡니다.

## 7. 목표 지표

모든 목표는 **초기 가설**입니다. Day 1 베이스라인 후 조정할 수 있지만 이유를 기록합니다.
**결과를 맞추려고 목표나 임계값을 바꾸지 않습니다.**

| 구분 | 지표 | 목표 | 왜 이 지표인가 |
|---|---|---|---|
| **안전 (필수)** | 음성 입력 기준 근거 없는 답변 | **0건** | 깨지면 다른 지표가 무의미 |
| 정확도 | STT 문자 오류율 (CER) | **10% 이하** | 한국어는 단어보다 문자 단위가 정확 |
| 정확도 | 조항 번호 인식률 (15문항) | **14/15 이상** | 숫자 하나만 틀려도 엉뚱한 조항 |
| 정확도 | 숫자 정규화 전/후 인식률 | 둘 다 기록 | 문제 발견 → 해결을 숫자로 |
| 일관성 | 텍스트와 같은 판정 비율 | **38/40 이상** | STT 오인식이 가드를 얼마나 흔드는지 |
| 일관성 | 오거부 증가 | **2건 이하** | 텍스트 기준 0건 대비 |
| 일관성 | 근거 조항 적중 (규정 안 18) | **17/18 이상** | 텍스트 기준 18/18 대비 |
| 지연 | STT RTF (처리/음성 길이) | **0.3 이하** | 5초 음성을 1.5초 안에 |
| 지연 | 전체 p50 / p95 (워밍업 후) | **2.0 / 3.0초 이하** | 지연 예산 3.0초 |
| 지연 | TTFT p50 | 기록 | 음성에서는 체감에 더 가까움 |
| 지연 | 거부 경로 전체 시간 | **STT + 0.05초 이내** | 거부는 LLM 호출 0회 |
| 지연 | **첫 요청 응답 시간** | **베이스라인 재측정 후 설정** | 아래 7-1 |
| 장애 | 장애 주입 4개 대체 응답 | **4/4** | 설계가 실제로 동작 |
| 장애 | 대체 응답까지 시간 | **구간 예산 + 0.2초 이내** | 장애가 나도 끊기지 않음 |

### 7-1. 콜드 스타트 베이스라인은 다시 잰다

v1은 "2.2초 → 0.8초"로 적었지만, **2.2초는 콜드 상태에서 18건 생성의 평균**이지
첫 요청 하나의 응답 시간이 아닙니다. 실제 첫 요청은 **7.2초**가 걸린 관측이 있습니다.

Day 2에 "서버 시작 후 첫 요청"을 명확한 절차로 재측정합니다
(Ollama 재시작 + 새 파이썬 프로세스 → 첫 요청 1회). **2.2초는 사용하지 않습니다.**

## 8. 환경 (2026-10-12 확인)

| 항목 | 상태 |
|---|---|
| GPU | **RTX 4070 Ti 12GB** — medium + qwen2.5:7b + bge-m3 동시 적재 가능 |
| faster-whisper | **1.2.1** (ctranslate2 4.8.2) 설치 완료 |
| fastapi / uvicorn | 이미 설치됨 |
| soundfile / librosa | 이미 설치됨 |
| ffmpeg | 없음 → **쓰지 않음** (녹음 스크립트로 대체) |
| jiwer | 없음 → **CER 직접 구현** (편집거리) |

### 8-1. Windows CUDA DLL 처리 (재현에 필요)

`ctranslate2` 가 `cublas64_12.dll` 을 못 찾아 CUDA 초기화에 실패합니다.
torch가 이미 번들하고 있으므로 **import 전에 경로를 등록**하면 해결됩니다.

```python
import torch, os
os.add_dll_directory(os.path.join(os.path.dirname(torch.__file__), "lib"))
from faster_whisper import WhisperModel   # 이제 device="cuda" 사용 가능
```

> Windows 전용 처리입니다. README에도 명시합니다.

### 8-2. 설치 연기 테스트 결과 (더미 신호 3초)

| 설정 | RTF | 목표 0.3 |
|---|---:|:---:|
| CPU small | 0.631 | ❌ |
| GPU small | 0.206 | ✅ |
| GPU medium | 0.066 | ✅ |

> **이 숫자로 모델을 고르지 않습니다.** 더미 신호는 출력할 토큰이 거의 없어
> medium이 빨라 보이는 착시가 생깁니다. 모델 선택은 실제 음성 10문항으로 합니다.

**CPU 폴백 계획은 삭제했습니다.** CPU small은 RTF 0.631로 목표 미달이고,
GPU가 해결됐으므로 불필요합니다. 미달 사실만 기록으로 남깁니다.

## 11. 면접 대비

| 예상 질문 | 답변 방향 |
|---|---|
| 지연은 어떻게 관리했나요? | 구간별 측정에서 병목을 말하고, 지연 예산과 대체 경로를 설명 |
| STT가 틀리면 어떻게 되나요? | 판정 일치율과 근거 없는 답변 0건. 오인식이 나도 가드가 막는 구조 |
| 왜 외부 STT API를 안 썼나요? | 사내 문서와 질문이 외부로 나가지 않는다는 제약 유지 |
| **왜 정규식을 안 넓혔나요?** | **`3조 2교대` 같은 표현이 제3조 조회로 오탐된다. 가드를 우회하는 경로라 단순 오인식보다 나쁘다** |
| 실제 통화에 붙이려면? | 스트리밍 STT, WebSocket, 동시 접속, 발화 끝 감지. 일부러 뺀 이유와 함께 |

말하면 안 되는 것: **"실시간 통화 시스템을 만들었다"**.
정확한 표현은 **"음성 입력 파이프라인을 만들고 지연과 장애 대응을 설계했다"** 입니다.

## 부록 A. v1에서 바뀐 것

| # | v1 | v2 | 이유 |
|---|---|---|---|
| 1 | 번호 인식률 90%, 평가셋 안의 2문항으로 측정 | **별도 15문항, 14/15** | 2문항으로는 0/50/100%만 나와 90% 판정 불가 |
| 2 | 숫자 정규화 언급 없음 | **STT 출력에만 적용, 전/후 기록** | 정규식이 숫자만 받아 한글 숫자를 놓침 |
| 3 | 콜드 스타트 2.2초 → 0.8초 | **첫 요청 실측으로 재설정** | 2.2초는 18건 생성 평균이지 첫 요청 시간이 아님 |
| 4 | 검색 0.3초 / 가드 0.05초 | **검색+가드 0.1초, LLM 1.3초** | 실측 0.01초로 과다 배정 |
| 5 | 타임아웃 방법 미정 | **스트리밍 + 데드라인, 음성 전용 함수** | 블로킹 호출은 중단 불가. 기존 함수는 보존 |
| 6 | API 프레임워크 미정 | **FastAPI** | Streamlit은 파일 업로드 API에 부적합 |
| 7 | CER 계산 기준 없음 | **공백·문장부호 제거 후 문자 단위, 정규화 전 원본** | 기준이 없으면 숫자가 흔들림 |
| 8 | 모델 선택도 40문항으로 | **별도 10문항** | 같은 데이터로 고르고 보고하면 과적합 |
| 9 | 로그 필드 추가 방식 미정 | **기본값 `None`** | 기존 호출을 깨지 않음 |
| 10 | "2시간 안 되면 CPU small" | **삭제** | CPU small은 RTF 0.631로 목표 미달. GPU 해결됨 |
| 11 | 녹음은 휴대폰 + 변환 | **PC 마이크 녹음 스크립트** | ffmpeg 불필요, 파일명·마이크 조건 일정 |
